## 0. One actual bug that breaks glanceability (fix first)

**The Media/Effect section does not follow the selection.** `selectLayer()` (index.html:3899) and `selectObject()` (index.html:3841) never touch `app.selectedMediaId`, so the lower "EFFECT" section keeps showing whatever was last clicked in the library or chain. State **c** proves it: the OBJECT section says *Alien skin* (Media = Alien skin, chain `Webcam → Motion cut → Alien skin`), but the EFFECT section underneath is still *Kaleidoscope · Reaction-Diffusion · Plasma* with Kaleidoscope sliders. A user turning "Hue" there is editing media that is not on the thing they selected, and nothing on screen says so.

Fix: in `selectLayer`/`selectObject`, set `app.selectedMediaId = (object||layer).mediaId` (and `_preview` off) before `updateLayerList()`. Everything in section 2 below assumes the media panel is *always* the selected thing's media.

## 1. Visual hierarchy — what the eye lands on vs what matters

Looking at `b_inspector_full.png` top to bottom, the strongest marks are: green `n36` pill, red trash cans (five of them above the fold), the blue `→ Kaleidoscope…` chip, blue `Use on layer`, blue slider thumbs, green `note 36…CC 7` list, red `Clear all`. None of those is "the layer I selected and the knob I'm about to turn". The things that *should* dominate are grey 10 px uppercase labels and a 13 px name that is styled as a transparent input (reads as text, not as the title).

Specific problems:

1. **Every section header has the same weight, including Scene and MIDI, which are context not focus.** Scene occupies the top 100 px of the inspector in every state and is never what you're editing while performing. MIDI's 9-row binding list is always expanded at the bottom (and its `--phys` green source column is the most saturated text in the panel).
2. **Label and value are the same colour** (`.param-row label` and `.param-row span` both `--muted` 11 px). You cannot pick the number out of the row at a glance. `.kv b` is already `--text`; the param-row value should match.
3. **Five red trash buttons visible at once** (Scene, Layer, Object, Effect headers + Clear all). `danger` red is the loudest colour in the palette; it should appear once per visible scope at most, ideally hidden behind hover or an overflow "…" menu.
4. **The purple 🎛 MIDI-learn button on every slider** (`button.purple`, 9 px, `#2b1d3f` bg, `#d8b4ff` text) is a strong vertical stripe of purple on the right of every row, 10 rows deep. 95 % of the time no binding exists. Only the *bound* state (e.g. `CC7`, which already renders green `--phys`) carries information.
5. **Section headers are indistinguishable from each other and from the in-section `h4`s.** PROJECTION / OBJECT / EFFECT / REACT / ARENA / OBJECTS / REACT / BUMP / MIDI — nine uppercase 10 px grey caps in `c_inspector_full.png`, two of them literally "REACT". There is no visual difference between "a thing you selected" (Layer, Object), "its media" (Effect), and "settings groups" (React, Arena, MIDI).
6. **The name field doesn't read as the title.** `.inline-name` is 13 px/600 in a borderless input at the same indent as the kv rows below it. It should be the biggest thing in the section (15–16 px) with the type icon/colour, and the h3 should shrink to a tag.
7. **"Visible" checkbox row** is the first row of every Layer/Object section, costing 22 px for a state that's already encoded by the 👁 button in the left panel header. Move it into the header actions as a toggle button.
8. **Sliders show no modulation state.** When React is set to `bass → Speed`, the Speed row looks identical to every other row. The row that is *live* should be visibly tagged (small `bass` badge after the value, in `--accent`), otherwise the user can't tell which knob the music is already moving.

### Priority fixes (hierarchy)

- Introduce three header tiers:
  - `--h-tier1` **object title**: name 15 px/600 `--text`, left-bordered 3 px in the type colour (`--accent`/`--mask`/`--phys`) like the layer chip, type tag 9 px uppercase in that colour on the right.
  - `--h-tier2` **group label** (React, Arena, Objects): 10 px uppercase `--muted`, as today, but with `margin-top:14px` and a 1 px `--line` rule *above*, not a full section border.
  - `--h-tier3` **context** (Scene, MIDI): collapsed one-liners, see §4.
- `.param-row span { color: var(--text); font-weight: 500; }` and keep `--muted` for the label. Values 11 px tabular as now.
- Hide 🎛 until hover: `.midi-ctl .midi-learn:not(.bound){opacity:0} .param-row:hover .midi-learn{opacity:1}`; keep `.bound` always visible (green `CC7` already works well).
- Move trash into header overflow: keep one `…` button per tier-1 header that opens Duplicate / Rotate / Delete; keep ↑↓ visible since they're reorder-while-performing actions.
- Drop the `Visible` row; make 👁 a toggle in the tier-1 header (same glyph as the sidebar so the two stay linked).

## 2. The effect chain — replace the button row with a vertical stage stack

### What's wrong now (`b_inspector.png`, rows "Plasma / → Reaction-Diffusion · Plasma / → Kaleidoscope · Reaction-Diffusion · Plasma")

- It's three `button.small` chips that wrap arbitrarily (first row has one chip + one chip, second row has one). Reading order is left-to-right-then-down, but data order is bottom-to-top of a stack. The arrows "→" fight the wrap.
- Each chip's label is the *full derived name* ("Kaleidoscope · Reaction-Diffusion · Plasma"), so the third chip repeats the text of the first two. At three stages you are reading "Plasma" three times and the row is 2 lines tall; at four it's 4 lines and ellipsised.
- `primary` (blue fill) on the selected chip is the same style as `Use on layer`, so "selected stage" looks like a call-to-action.
- `× Remove top effect` is a red button that removes the *top* stage regardless of which chip is selected. No per-stage remove, no bypass, no reorder.
- `+ Effect` is a `<select>` labelled like a param row; it sits visually with the Media select and Upload button rather than at the end of the chain.
- The params for the selected stage are in a **separate section 100 px lower**, with its own name, its own `Source` dropdown (which duplicates the chain), its own trash (deletes from library, a far more destructive action than "remove from chain", styled identically).

### Proposed pattern: "Stack" card list, params inline, no separate Media section

Render inside the Layer/Object section, replacing both the `Media` select row and the current `effectChainRow()`, and *absorbing* the Media/Effect section:

```
PROJECTION  ▌ Plasma                        ↑ ↓  …
┌──────────────────────────────────────────────────┐
│ ● Kaleidoscope             ⏻   ⋮   ×            │  ← top stage (applied last), selected = highlighted
│   Symmetry  ━━━━━●━━━━━  6                     │  ← its params inline, only when selected
│   Rotate    ━━━━●━━━━━━  0.005                 │
│   …                                             │
├──────────────────────────────────────────────────┤
│ ○ Reaction-Diffusion        ⏻   ⋮   ×           │  ← collapsed stage: one 24px row
├──────────────────────────────────────────────────┤
│ ■ Plasma            (source)    ▾ change        │  ← base media, always last, select on click
└──────────────────────────────────────────────────┘
          + Add effect ▾                             ← ghost button, full width, under the stack
```

Element spec, top to bottom:

1. **Container** `.stack`: `background: var(--panel2); border:1px solid var(--line); border-radius:8px; overflow:hidden`. Rows separated by `1px solid var(--line)`. Order: top-of-chain first (what you see on stage) down to base media last. This matches "layers in a compositor" and matches the left panel's top=front ordering.
2. **Stage row** `.stage` (height 28 px, `display:grid; grid-template-columns: 14px 1fr auto`):
   - 14 px **kind glyph**: `✦` for effect in `--gen` purple, `■` for base media in the kind colour used by the thumb badge (camera mint, youtube red, gen purple, file grey). This is the only place purple appears in the stack, so the eye can count effects.
   - **Short name**: just the generator label ("Kaleidoscope", "Reaction-Diffusion", "Plasma"), 12 px `--text`. *Never* the derived `A · B · C` name — the stack already shows the composition. Keep the derived name only as `media.name` for the library caption.
   - **Row actions**, 20×20 ghost buttons, visible on hover or when row selected: `⏻` bypass (toggles a per-stage `bypass` flag, row text goes `--muted` + strikethrough glyph), `⋮` move up/down + "save as preset", `×` remove **this** stage (re-parents the stage above to the stage below, so you can pull a middle effect). Remove is `--muted` by default, red only on hover.
   - **Selected row**: `background: rgba(74,158,255,0.10); box-shadow: inset 3px 0 0 var(--accent)`. Not a filled blue button.
3. **Inline params** under the selected stage only: the existing `.param-row` list, indented 14 px to align under the name, `padding-bottom:6px`. Collapsed stages are one row. This removes the separate "EFFECT" section, the duplicate `Source` dropdown, and the ambiguity in §0.
4. **Base row**: same row, kind glyph, name, and a right-aligned `change ▾` which opens the existing media `<select>` (or focuses the library). Clicking the row selects the base media so its generator params (Plasma speed/scale) show inline too — the base is just stage 0.
5. **`+ Add effect`**: a single full-width ghost button (`border:1px dashed var(--line); color: var(--muted); height:26px`) directly *under* the stack, which opens the same five-item list as a small popover. Don't render it as a labelled `<select>` param row. Adding pushes a new row onto the top and auto-selects it so its params appear immediately.
6. **Library-side actions** (the old header's `Use on layer`, 🗑 remove from library, Bounce it) move to the thumbnail's hover `×`/context — they are library operations, not inspector ones. `Use on layer` becomes unnecessary once clicking a thumb already does that (the title tooltip says it does).
7. **React block** stays, but belongs to the selected stage, rendered after its params inside the row, under a tier-2 label `REACT` — and when `Signal ≠ off` the targeted param row gets a `bass` badge (§1.8).

Visual weight, strongest to weakest: selected stage row (accent inset bar + tint) > stage names (12 px `--text`) > param values (`--text` 500) > labels (`--muted`) > row actions (ghost, hover-reveal) > `+ Add effect` (dashed ghost).

Also apply the same component for physics objects: the OBJECT section in state **c** has exactly the same `Webcam → Motion cut → Alien skin` row, with Size/Opacity/Spin rows pushed below it; put Size/Opacity/Spin *above* the stack (they're the object's own params), stack below.

## 3. Left panel

### Library thumbnails (`a_sidebar.png`)

What works: the 4:3 canvases themselves — you can recognise Plasma, Perlin, Hexagons instantly. What doesn't:

- **"In use" is a 7 px green dot top-right** that competes with the `×` delete which appears in the exact same spot on hover (`.thumb.inuse:hover::after{display:none}` – the signal vanishes when you look at it). In state a, 12 of 20 thumbs are in use; the dot is too small to count. Suggest: in-use = full `2px solid` border in `--phys` at 60 % + the dot; unused = as now. Selected keeps `--accent`. Then the grid reads as "green = on stage, blue = inspecting" at a glance.
- **Effects with no source render black** (Motion cut, Neon edges, Posterize, Pixelate, Tunnel are near-black tiles with only an 8 px "FX" badge). A black 84×63 rectangle looks like a broken/offline item. Render a placeholder: the generator's glyph (`✦`) centred at 20 px in `--gen` at 35 % opacity plus the caption "needs source" in 8 px. Or draw the effect on a built-in test card so the tile shows what the effect *does*.
- **Kind badge** (`.thumb .kind`, 8 px) is legible but does not distinguish *effect that is applied to something* ("Kaleido of plasma", "Reaction-Diffusion · Plasma") from *effect with no source*. Use `FX` for the former and `FX ·` with the dim placeholder for the latter, or colour the badge `--gen` only when it has a source.
- **Caption** 9 px and ellipsised at ~12 chars ("Reaction-Diffu…", "Kaleido of plas…"). The derived names are long because they are `effect · source`. Once names are short (section 2), captions fit. Also raise caption to 10 px; there is room with a 2-line clamp.
- **The generator `<select>` + "+ Pattern" button** at the top of the library is the only place to create an effect, but it's a dropdown with 13 items where the ✨ ones are effects. Since effects are now added from the stack, this select should list only base generators and the ✨ items can go.

### Scene pads

Fine. The pads are the one element in the sidebar with a clear selected state (`--accent` fill). Two nits: `1 · n36` crams two facts into 9 px; drop the `n` prefix inside the pad (`1 ▸ 36`) or show the note only when bound. The `+ Scene` button in the header duplicates a `.pad.add` style that already exists in CSS; use one.

### Layer rows (`a_sidebar.png`, `c_sidebar_full.png`)

- **Name + info both say the same thing** for 9 of 12 rows ("Stripes / Stripes", "Webcam / Webcam"). Suppress the info line when `layer.name === media.name`; use it for *state* instead: `3 fx · bass→speed · hidden`.
- **The 4 px chip colour is the only type signal** (blue projection / amber mask / green physics) and it is 4 px wide next to a 300 px row. Fine for pros, invisible to glance. Add the type glyph (`▣ ◉ ◈`, already used in the inspector h3) before the name in the chip colour, 11 px.
- **👁 and 🗑 are always visible**, 24 rows × 2 emoji. Emoji render at full saturation regardless of `color`, so these two are the brightest things in the row. Make them hover-reveal (keep 👁 visible only when the layer is *hidden*, rendered as 🚫 in `--muted` as the obj rows already do).

### Physics object rows (`c_sidebar_full.png`)

Indent 18 px with 10 px dot chip works; the dot colour is genuinely useful because it matches the object's colour on stage. Issues:

- **`r 7` / `r 12` / `r 9` labels**: radius is only meaningful relative to others, and you can see size on stage. Replace with what you *can't* see on stage: kind + media for media objects ("sprite · Alien skin"), nothing for plain shapes. If radius stays, write `r=7` or `⌀ 14`, not `r 7`.
- **Three buttons per object row** (👁 📋 🗑) × 9 objects = 27 emoji in a 300 px column. Hover-reveal all three.
- **Media objects get a purple `--gen` dot** even when the media is a webcam/video, so "Remote mp4 (flower)" shows purple. Use a 10×10 thumbnail crop of the media instead of a dot for media objects; keep dots for shapes.
- **Object names "● circle", "■ rect"** repeat the glyph in the name and the chip; drop the glyph since the chip exists, or drop the chip.

## 4. Collapse / sticky / redundant

Collapse by default (remember state in localStorage):

- **Scene section** → one 28 px sticky header line: `SCENE 1 · Grid: every source · n36 · 12 layers` with the 💾/📑 buttons on hover. Expand on click to edit name/rebind.
- **MIDI section** → header line `MIDI · 9 bindings · PC→scenes ✓`, collapsed. It is global state, not per-selection, and currently occupies 300+ px in every state.
- **React** (per media, and the physics one) → collapsed one-liner `REACT  off` / `REACT  bass → Size 0.4`, expand on click. When active, show the badge on the target slider (§1.8) so collapsing loses nothing.
- **Arena / Objects / Bump** in `#physicsPanel` → keep Arena open (those are the performance knobs), collapse Bump (set-once hotkey) and move the "Grab any object…" notice into a `title` tooltip.

Sticky:

- The **tier-1 header of the selected thing** (`PROJECTION ▌ Plasma`) should be `position: sticky; top: 0; background: var(--panel); z-index:1` inside `#inspector` so the user always knows which object the sliders below belong to while scrolled. Same for the `LAYERS` header in the sidebar (the layer list is the one that scrolls off; library should become collapsible so layers get the room).

Redundant (remove):

- `Visible` checkbox (sidebar 👁 does it).
- `Media` select on the layer + `Source` select on the effect + the chain chips: three UIs for one graph. The stack replaces all three.
- The `layers 12 / MIDI note 36` kv rows under Scene (the pad already shows `1 · n36`, and layer count is visible in the list).
- Second `h3` tier-1 header "EFFECT / Use on layer / 🗑" once params render inline.
- Two different "React" blocks visible at once in state c (media React + physics React). With the stack, the media React lives inside the stage row; the physics React lives under Arena.

Spacing: section padding `10px 12px` is fine; the problem is that *every* section has a full-width `--line` border so Scene/Layer/Media/MIDI look like four equal peers. Use the border only between tier-1 blocks; inside, use `margin-top:14px` for tier-2 labels.

Colour budget after changes: `--accent` = selection (thumb border, layer row, stage row, scene pad, slider fill). `--phys` green = "live/in use/bound" (in-use thumb border, bound CC chip, physics type). `--gen` purple = "effect" only (stage glyph, FX badge). `--danger` red = hover only. That reduces the current always-on reds from ~6 to 0 and purples from ~10 to the count of effects.
